# ページを軽く・速くする

ユーザーの多くはスマホで、回線が遅いこともある。**届ける量を減らすこと**がいちばん効く。フレームワークや道具を変えても速くはならない。

## 1. 測る

```bash
npm run speed                      # 主なページ
npm run speed -- about kodomo/make # 指定したページだけ（先頭に / を付けない）
```

`site/` を手元で配って Lighthouse（スマホ想定）で測り、性能・LCP・転送量・アクセシビリティ・コンソールのエラーを表にする。前回との差も出る。結果の JSON は `scripts/.speed/<ページ>.json`。本番の URL は叩かない。

## 2. 重い原因を見つける

JSON の次の項目を読む。
- `audits['network-requests'].details.items`：読み込んだファイルと大きさ。大きい順に並べる
- `audits['render-blocking-insight']`：表示を止めているファイル
- `audits['errors-in-console']`：エラー（`/api/` の 404 は手元にないだけなので無視してよい）

## 3. 直し方（効く順）

1. **使っていない読み込みを外す。** ページの `<script src>` ごとに、そのページの JS がその `window.XXX` を本当に使っているかを grep で確かめる。過去に、テーマのトップが使っていない自治体データ・文面・PDF作成のプログラムを約1.2MB読んでいた。
   - 外すと `common.js` が「文面のデータを読み込めませんでした」と画面に出すことがある。データを使わないページは `<body data-skip-data-check="1">` にする（`test/pages-data.test.js` が見張る）。**画面の上に出る文言はコンソールのエラーにならないので、ブラウザで `.data-error` がないかも見る**
2. **全国分のデータを、要る分だけにする。** 自治体ごとのデータは `site/data/pref/<番号>.js` に都道府県ごとに分けてあり、`site/js/pref-data.js` の `PrefData.load(pref)` で読む。新しい自治体ごとのデータを作ったら、`scripts/split-pref-data.js` に足す
3. **使うときに読む。** ボタンや入力欄を触ったときに初めて要るデータは、そのときに `<script>` を足して読む（例：`wizard.js` の `needKana`）
4. **ページ末尾の `<script>` に `defer` を付ける。** 順番は保たれる
5. PDF 用のフォントなどは、PDF を作るときだけ読む（すでにそうなっている。崩さない）

**しないこと**：インラインの `<script>`・`<style>`・`on*=` を書く（CSP で止まり、`npm test` も落ちる）。外部の CDN から読み込む。

## 4. 確かめる

- `npm run speed -- <ページ>` で前後の数字を比べる
- 機能が壊れていないかを、実際のブラウザで最後まで操作して確かめる（`browser-drive` スキル）。陳情書をつくる画面なら、求める内容 → 都道府県 → 議会 → あなた → 文面確認 まで進め、電話・公式サイト・行き方・受け付け方が出ることを見る
- `npm test` と `npm run lint`
- `site/roadmap.html` の「ページを軽く・速くする」の数字を更新する
