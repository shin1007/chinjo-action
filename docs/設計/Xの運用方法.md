# X の運用方法（まとめ）

最終更新：2026-11-23。X の運用について、これまでに決めたこと・調べたこと・確かめられていないことを1つにまとめた。細かい説明は、各項目のリンク先を見る。出典のうち「二次資料」は、検索結果の要約や運用会社・ブログの記事で、公式の資料では確かめていない。

## 1. 位置づけ
- **目的**：陳情アクション（https://chinjo-action.vercel.app/）を知ってもらい、陳情書をつくる人を増やす。X では、機能の更新・使い方・陳情の項目の紹介・調べた結果を知らせる。
- **運営者**：個人。団体ではない（サイトの全ページのフッターと `/trouble` に明記している）。プロフィールにも同じことを書く。
- **アカウント**：運営者が既に持っているアカウントを使う（新しく作らない）。投稿は手で行う。**自動投稿は必須としない**（[SNS自動投稿の設計](SNS自動投稿の設計.md)に設計とスクリプトがあるが、保留）。
- **収益化**：いまは目標にしない（下の「9. 収益化・お金・税金」）。

## 2. 頻度（二次資料と、私の提案）
- **頻度は固定せず、4週間かけて試す。** 投稿を増やすと1本あたりの表示が下がる可能性がある。
  - 最初の2週間：平日1日1本（時間は固定）、週末は1本まで。
  - 次の2週間：平日1日2本（時間を変えて）。
  - 比べるのは、1本あたりの24時間後の表示回数とリンクのクリック。大きく落ちなければ増やし、落ちれば減らす。
- 続けられる頻度が先。続かないなら週3本に落とす。
- **繰り返しは問題ない**（タイムラインは数時間で流れ、フォロワーは入れ替わる）。ただし同じ文面は避け、**切り口・書き出し・画像・リンク先を変える**。同じ項目の取り上げ直しは3週間あけてから。

## 3. 時間（二次資料）
日本の目安は、平日の7〜8時・12時前後・20〜22時（根拠のデータは示されていない）。読者の生活が違うので、次を曜日ごとに回して比べる。

| 時間帯 | 試す相手・型の例 |
|---|---|
| 朝 7:30 | 通勤・通学の人。短い知識（C）・入口（A） |
| 昼 12:15 | 昼休みの人。項目（B）・調査の知らせ（D） |
| 夜 20:30 | 仕事のあとの人。項目（B）・海外・読み物（F・G） |
| 夜 22:30 | 育児を終えたあと・夜型の人。子どもの権利・男女平等の項目（B） |
| 週末 朝9:00／夜21:00 | 長めの読み物（G） |

投稿の直後に返信に答えられる時間に出す。1本ごとの数字を `docs/調査/X投稿の記録.csv` に記録する。詳しくは [Xの時間とフォローの方針](Xの時間とフォローの方針.md)。

## 4. 内容の型
サイトには陳情の項目が全部で134項目あり（国あて76・自治体あて58）、項目ごとに「この陳情の意義」のやさしい説明ページがある（例：`/dansei/easy/l_bias_men`）。

| 型 | 内容 | リンク先 |
|---|---|---|
| A 入口 | 約480円・登録不要・住所氏名をサーバーに送らない・50秒の動画 | `/` |
| B 項目 | 項目を問いかけ＋理由1つ | `/<テーマ>/easy/<項目id>` |
| C 知識 | 紹介議員はいらない・署名の基準はない・意見書で国へ・SNSとの違い | `/about` |
| D 調査の知らせ | 調べた自治体の数・郵送の扱い | `/coverage`、`/kakunin` |
| E 運営の透明性 | 機能の更新・訂正・確かめられていないこと | `/trouble` |
| F 海外 | 英国の電子請願など。**確かめたものだけ** | note |
| G 読み物へ | note の記事 | note |
| H 結果・声 | 提出数・結果の集計。**集計は準備中**（`/` の「これまでの歩み」）。出るまで使わない | `/` |

- 6テーマ×型×書き出し（問いかけ・数字・よくある誤解・時期）で、200本以上になる。
- 1週間のリズムの例：月 B／火 C／水 A／木 B（別のテーマ）／金 D・E／土 F・G／日 休みか返信。
- 文の例と、軸の掛け合わせは [X投稿のパターン](X投稿のパターン.md)。初回のスレッド案（7件）は [X投稿](../見本/X投稿.md)。
- 海外の材料で確かめられているのは、英国議会の電子請願（1万署名で政府が回答・10万で討論の対象になりうる・6か月・出せるのは英国市民と居住者）とスコットランド議会の請願。ドイツ・欧州議会・欧州市民イニシアティブ・日本の請願法の条文は未確認。日本の制度と同じものとして書かない。[海外の請願制度](../調査/海外の請願制度.md)

## 5. 書き方のきまり
1. リンクは1投稿に1つ。長いときはスレッドにし、1件目で結論、2件目以降で根拠。
2. 事実・数字は、サイトに載せているものだけ。出典は返信に付けてもよい。
3. 確かめられていないことは、そう書く。
4. 特定の議員・政党・自治体・個人を批判しない。議員にメンションしない。
5. 返信・引用は運営者が読む。答えられないことは、そう答える。
6. ハッシュタグは1〜2個。「#拡散希望」は使わない（効果が確かめられていない）。
7. 画像には説明（代替テキスト）を付ける。
8. **選挙の時期の投稿は、公職選挙法との関係を確かめるまで控える**（未確認）。
9. 誤った投稿を見つけたら、削除か訂正の返信を出す。訂正は、何を直したかを書く。

## 6. フォローとリスト（二次資料）
- **情報収集は、フォローより非公開リスト。** 議会・自治体・省庁・裁判所・報道・研究者・団体（賛成・反対の両方）を、リストに入れて読む。
- **フォローは、理由のあるアカウントだけ。** 最初の2週間は1日5〜10件、慣れても1日20件まで。X の機械的な上限は1日400件（検索結果の要約）だが、近づかない。**一括フォロー、フォローと解除のくり返しはしない**（スパムとして扱われるおそれ）。フォロー後1週間のうちに、1回やりとりする。「フォロバ100」目的のアカウントはフォローしない。
- 議員は、本人の公式アカウントだと確かめてから、必要に応じて。特定の政党にかたよらない。
- 候補は、Grok に公式アカウントの一覧を頼み（`scripts/collect-prompt-grok.md` の B）、運営者が1件ずつ開いて確かめる。個人のアカウント名は、公開のリポジトリに書かない。

## 7. Grok の使い方
- **X の投稿は、こちらから自動では読めない**（ボットの拒否・ログインが要る）。そこで、**X 上の情報の収集に Grok を使う**。依頼文は `scripts/collect-prompt-grok.md`（A：話題の収集、B：公式アカウントの一覧）。
- Grok の回答は**二次資料**。事実の根拠にも、陳情の文面にも使わない。保存して、一次資料の候補に当たって確かめ、確かめられたものだけを材料にする。X の投稿の URL は運営者が開いて確かめる（「X確認済み」の印）。
- 下書きの外部レビューは従来どおり `scripts/review-prompt-grok.md`。投稿文の自動生成・自動返信には使わない。Grok の API の規約は未確認。

## 8. 自動投稿（任意・保留）
- **投稿は手でコピー＆ペースト**（画像・動画も、保存して添付）。**リマインド**は、Slack（`scripts/notify-slack.js`・`slack-remind` ワークフロー。予定の15分ほど前に、本文・画像・動画のリンクが届く）か、投稿予定のカレンダー用のファイル（.ics）で行う（予定の15分前と時刻に通知。説明に本文が入る）。**動画つきの予約**は、X の予約投稿を使う。API での動画の自動投稿は、手順が確かめられていないので保留。
- X の API で、告知を自動で投稿できる（二次資料：従量課金で無料枠は新規にはなく、1件約0.015ドル、URL つきは約0.20ドル）。自動化のアカウントは「自動化」のラベルとプロフィールの明記が要る。返信・メンションの自動化は禁止。
- スクリプトとワークフローは作ってある（`scripts/post-x.js`、`.github/workflows/post-x.yml`、投稿の予定 `site/data/sns-queue.jsonl`）。**使うなら**、ボット用の別アカウントを作り、鍵を GitHub の Secrets に入れ、承認を付けて動かす。今は保留。[SNS自動投稿の設計](SNS自動投稿の設計.md)

## 9. 収益化・お金・税金
- X の収益分配の条件・受付状況は、公式ページが自動では読めず**未確認**（`docs/調査/SNS収益化の規約に当たれなかった資料.md`）。二次資料では、収益の分配を受けるには認証済みフォロワーや有料のプレミアムが要るとされる。**収益化は、確かめるまで目標にしない。** 収益が出ても、陳情の内容や載せる資料は変えない。
- 運営費の応援の受け付けは、**政治資金規正法に当たるかを確かめるまで始めない**（[記録](../調査/政治資金規正法と応援の受け付け.md)）。
- 収入を受け取ったときの税金の確認は、[資金調達と税金](../調査/資金調達と税金.md)。運営者の個人の事情は、公開のリポジトリには書かない。

## 10. 4週間の進め方
| 週 | 投稿 | フォロー・リスト |
|---|---|---|
| 1 | 平日1日1本（朝か昼）。型A・C中心 | 公式アカウントを調べ、非公開リストを作る。フォロー1日5件 |
| 2 | 平日1日1本（夜20:30）。型B | リスト150件まで。フォロー1日5〜10件、返信を週5件 |
| 3 | 平日1日2本（朝＋夜）。型D・E | フォロー1日10件まで |
| 4 | 平日1日2本（昼＋夜22:30）。週末は型G | 記録を見て、時間と型を決め直す |

以降は、2週間ごとに記録を見て、反応のよい型・時間を増やす。

## 11. まだ確かめられていないこと
- X の仕様・アルゴリズム・アナリティクスの項目（公式の資料が読めていない）。
- X の収益化の条件、自動化の規約の最新、フォロー制限の最新の数字。
- 選挙の時期の投稿と公職選挙法。
- 海外のうち、ドイツ・欧州議会・欧州市民イニシアティブ・日本の請願法の条文。
- 政治資金規正法に当たるか、収益・応援の税の扱い。
- Grok が X 全体を網羅しているか、Grok の API の規約。
