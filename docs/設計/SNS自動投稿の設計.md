# SNS の投稿の設計（X は自動、note は下書きまで自動）

2026-11-23。X・note の公式ページは自動アクセスで読めなかったため（[記録](../調査/SNS収益化の規約に当たれなかった資料.md)）、以下の条件は**二次資料**（検索結果の要約・解説記事）による。実装の前に、運営者がブラウザで公式ページを開いて確かめる（[TODO](../TODO/SNS運営のTODO.md)）。

## X：ボットで投稿できる
- **できる**。X API（POST /2/tweets）で投稿できる。
- **料金（二次資料）**：2026年2月から従量課金（前払いのクレジット）。無料枠は新規にはない。投稿1件が約0.015ドル、**URL つきは約0.20ドル**と書く記事が多い。月に10〜20本なら、URL つきでも月2〜4ドルほど。記事によって単価が違うので、開発者コンソールで確かめる。
- **決まり（二次資料。X の自動化の規約）**：API で投稿するアカウントは、プロフィールの「自動化」ラベルをオンにし、プロフィールに「自動投稿である」ことと運営者を書き、人が運営するアカウントへのリンクを置く。返信・メンションの自動化と、トレンドへの自動投稿は禁止。ブラウザの自動操作・スクレイピングは禁止（API だけを使う）。違反すると永久凍結のおそれ。
- **運営者の個人アカウントを使い回さない**：ボット用のアカウントを1つ作る（人が運営するアカウントは別に持つ。電話番号を使うのは、どちらか1つ）。

### やり方（作る順）
1. X の開発者コンソールでアプリを作り、読み書きの権限（OAuth 1.0a の4つの鍵、または OAuth 2.0）を取る。
2. GitHub の Settings → Secrets に鍵を入れる。**鍵はリポジトリに書かない**（公開リポジトリ）。
3. `scripts/post-x.js`（Node の標準だけで書く）：投稿の文を1つ受け取り、API に送る。`--dry-run` では送らず、文と文字数だけ出す。
4. `.github/workflows/post-x.yml`：`site/data/sns-queue.jsonl`（投稿の予定。1行1件、文・リンク・予定日・状態）に、main へ入った新しい行があれば、1件ずつ投稿する。GitHub の Environment に「承認が必要」を付け、運営者が承認した分だけ投稿されるようにする（最初の1か月はこの形）。
5. 機能更新のたびに、Claude が PR の中で `sns-queue.jsonl` に投稿の文を足す。文には、サイトの画面（URL と位置）と、変わったことだけを書く。事実・数字は載せない（載せるときは一次資料の出典つき）。

### 守ること
- 同じ文の連投・返信やメンションの自動化はしない。1日の上限を決める（例：3本）。
- 投稿は予定日まで待つ。失敗したら再送せず、運営者に知らせる。
- 鍵が無い・承認が無いあいだは動かさない（サイトの「準備中」のまま）。

## note：公式の API は個人には開かれていない（二次資料）
- note の公式の記事投稿 API は、note pro の契約者が、対応する外部サービスから**下書き**に送る形に限られる（公式のヘルプのページの題名で確認。本文は読めていない）。個人が自作ツールから公開まで自動で行う公式の方法は、見つかっていない。
- 非公式の API（Cookie で認証）を使う記事はあるが、規約で禁じられているか確かめられておらず、アカウントの停止のおそれがある。**使わない**。
- したがって note は、**記事の下書きを Claude が書いてリポジトリ（`docs/投稿/note/`）に置き、運営者が note の画面に貼って公開する**形にする。公開の前に運営者が必ず読む。

### note の更新の頻度
- **大きめの更新のとき**：項目が増えた、新しいテーマが足された、など。更新の一覧（何が・どこに増えたか）と、画面の URL を書く。
- **週に1回のテーマ紹介**：6テーマ（dansei・kenko・kodomo・nihonjin・shiho・sonota）を順に。1本の構成は、
  1. このテーマで、サイトが扱う陳情の項目（`/<テーマ>/make` の位置）
  2. 根拠の法令（条文の原文を e-Gov 法令検索で確かめたものだけ）
  3. 根拠の研究・公式の調査（論文・官公庁の資料の原文で確かめたものだけ）
  4. 確かめられていないこと（`/trouble` と同じ書き方）
  5. 陳情書を作る入口へのリンク
- 根拠は、各テーマの `reasons.js`・`asks-*.js` に書いてあるものを元にし、書くときにもう一度一次資料で確かめる。確かめられなければ載せない。
