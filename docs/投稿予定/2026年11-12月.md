# X 投稿予定（2026年12月1日〜12月27日）

コピー＆ペーストで使う投稿の予定。**自動では投稿されない。** 予定の時刻に、運営者が X に貼って投稿する。
最終更新：2026-11-28（X の投稿を始めるのに合わせ、全部の予定を1週間後ろにずらした。アカウントは https://x.com/pedmWay1hR85704 ）。方針・根拠は [Xの運用方法](../設計/Xの運用方法.md)。

## 使い方
1. 予定の日時が来たら、その見出しの下の「本文」のコードブロックを、そのままコピーして X に貼る（右上のコピーボタンが使える）。
2. 「画像」があれば、X の投稿画面で添付する。項目（B）の画像は、テーマの紹介画像で、付けても付けなくてもよい（画像は最大4枚。GIF は1つだけで、画像とは一緒に付けられない）。画像の説明（代替テキスト）には、画像に書いてある件名を入れる。
3. 「投稿前の確認」の1行を見て、数字や記述が変わっていないか確かめる。**数字が入った投稿（D）は、サイトの最新の値に直してから出す。**
4. Slack にリマインドを送った予定は、自動で `[x]`（済み）になる（出せなかった日は飛ばしてよい）。Slack のリマインドの「X の投稿画面を開く（本文入り）」ボタンを押すと、本文が入った X の投稿画面が開く。24時間後に Slack に「数字を入れる」知らせが届くので、毎朝のメニューの **n** で表示回数などを入れる（[X投稿の記録.csv](../調査/X投稿の記録.csv) に足して公開する。`node scripts/post-stats.js` でも同じ）。
5. 予定の時刻に出せなかったら、そのまま1日ずらしてよい。出せなかった日は飛ばしてよい（続けることが先）。

## リマインド（カレンダーに入れる）
投稿の予定は、カレンダー用のファイル [2026年11-12月.ics](2026年11-12月.ics) にしてある（34件）。取り込むと、予定の15分前と時刻に通知が出る。**予定の「説明」に、本文・画像・投稿前の確認が入っている**ので、スマホで予定を開いて、説明から本文をコピーして X に貼れる。
1. GitHub でこのファイル（2026年11-12月.ics）を開き、「Download raw file」で保存する。
2. Google カレンダー（パソコンのブラウザ）→ 設定 → インポート／エクスポート → インポート → 保存したファイルを選び、入れ先のカレンダーを選ぶ。
3. 通知が付かなかったら、そのカレンダーの「通知」の既定を設定する（取り込み時に通知が引き継がれない場合がある）。
4. この予定を直したら、`node scripts/schedule-to-ics.js docs/投稿予定/2026年11-12月.md` で作り直し、カレンダーの古い予定を消してから取り込み直す（投稿済みの `[x]` は書き出されない）。

## Slack でリマインドを受け取る
予定の15分ほど前に、**Slack に本文・画像・動画の場所が届く**。X への投稿は、運営者が手で行う（自動では投稿しない）。
- 届く内容：見出し（日時・型）／本文（コードブロック。長押し・コピーボタンでコピーして X に貼る）／画像（Slack に表示される）／動画・GIF のリンク／投稿前の確認とリンク先。
- 画像・動画は、予定の「画像」の行のファイルを、公開リポジトリの URL で知らせる。**スマホでは、Slack で画像を長押しして端末に保存し、X の投稿画面で添付する**（画像を直接貼れるかは、端末と X のアプリによる。確かめていない）。動画は、リンクを開いて保存する。
- 設定（1回だけ。Slack の画面の名前は変わることがある。Slack の公式の説明で確かめる）：
  1. Slack のワークスペースで、通知を受け取るチャンネルを決める（自分だけのチャンネルでよい）。
  2. https://api.slack.com/apps で新しいアプリを作り、「Incoming Webhooks」をオンにして、そのチャンネルあての Webhook URL を作る。
  3. GitHub のこのリポジトリの Settings → Secrets and variables → Actions に、`SLACK_WEBHOOK_URL` という名前で、その URL を入れる（**URL は秘密。リポジトリや Slack の公開の場所に書かない**）。
  4. Actions の「slack-remind」を、Run workflow で動かす。`now` に `2026-11-24T07:20:00+09:00`、`dry_run` に `false` を入れると、11/24 の最初の予定が、試しに Slack に届く。
- しくみ：`.github/workflows/slack-remind.yml` が15分ごとに動き、`scripts/notify-slack.js` が、これから20分以内の未投稿の予定を探して送る。投稿したら、予定の `[ ]` を `[x]` にする（`[x]` は送られない）。GitHub の定期実行は、数分〜十数分遅れることがある。
- Slack を使わないときは、前の「リマインド（カレンダーに入れる）」を使う。

## 動画を付けて投稿する
- 動画（や GIF）は、予定の「画像」の行に、**リポジトリの中のファイルの場所**（例 `docs/投稿予定/media/kenko-intro.mp4`）を書いておく（複数は「、」で区切る）。Slack のリマインドに、リンクが付く。動画は、GitHub の1ファイル100MB未満にする。X の1件の投稿に付けられるのは、画像なら4枚まで、動画・GIF は1つだけ（画像とは一緒に付けられない）。
- **予定の日時に投稿を自動で出したい場合は、X の「予約投稿」を使う**（パソコンのブラウザの投稿画面で、日時を指定して予約できる。動画も付けられる。使える条件・動画の長さの上限は、X の公式の説明で確かめる）。本文は、この予定のコードブロックを貼る。
- X の API で動画つきの投稿を自動で出す方法（`scripts/post-x.js` の拡張）は、保留にしている。動画のアップロードの手順が、資料によって食い違っていて（新旧のエンドポイント、認証の方式）、公式のページが自動では読めず、確かめられていないため。API の鍵が入り、公式の手順を確かめられたら作る。

## 前提
- 第1週（12/1〜12/7）は平日1日1本（朝か昼）、第2週（12/8〜12/14）は夜 20:30、第3週（12/15〜12/21）は朝 7:30＋夜 20:30、第4週（12/22〜12/28）は昼 12:15＋夜 22:30。週末は1本まで。日曜は原則休み。
- **第3週から1日2本に増やす前に、第1・2週の数字を見て、増やすか決める**（増やさなければ、夜の分だけ出す）。
- 型：A 入口／B 項目／C 知識／D 調査の知らせ／E 運営の透明性／F 海外。
- 項目（B）は、サイトの意義のページ（`/テーマ/easy/項目id`）の題と同じ内容。**新しい事実・数字は足していない。**
- 項目の選び方：6テーマを、4週間で回した（子どもの権利・男女平等・国民の健康・司法への参加は複数回、日本人の権利・その他は少なめ）。賛否の分かれる項目は、題の言い回しをサイトのままにしている。出すかどうかは運営者が決める（出さなければ飛ばす）。
- ハッシュタグは1〜2個。効果は確かめていない。
- 全文、X の数え方（全角2・半角1・URLは23）で280以内であることを `scripts/post-x.js` の計算で確かめた。
- 出典のある記述（柏崎市議会・岩倉市議会・英国議会）は、投稿前に出典の元ページが変わっていないか確かめる。
