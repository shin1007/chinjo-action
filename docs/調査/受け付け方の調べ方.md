# 自治体の受け付け方の調べ方（手伝ってくださる方へ）

陳情書を出す人がいちばん困るのは、「この議会は郵送で出して審査してくれるのか」「メールや電子申請で出せるのか」「住んでいなくても出せるのか」が、議会ごとにばらばらなことです。全国 1787 の議会・自治体を、1つずつ公式サイトで確かめています。プログラミングの知識はほとんど要りません。

## 1. 担当を決める

GitHub の Issue に「〇〇県をやります」とコメントしてください（重なりを防ぐため）。1回のプルリクエストは、1つの都道府県か、10自治体くらいまでがおすすめです。

まだ調べていない自治体は、次のコマンドで人口の多い順に出ます。

```sh
node scripts/intake.js todo page        [都道府県]   # 陳情の案内ページが見つかっていない
node scripts/intake.js todo mail        [都道府県]   # 郵送で出した陳情を審査するか
node scripts/intake.js todo online      [都道府県]   # メール・電子申請で出せるか
node scripts/intake.js todo nonresident [都道府県]   # 住民以外の陳情の扱い
node scripts/intake.js todo yobo        [都道府県]   # 首長あての要望の出し方
```

## 2. 公式サイトで確かめる

- 見るのは、**議会・自治体の公式サイトの案内ページだけ**です（「請願・陳情」「陳情の出し方」「市長への手紙」「市民の声」など）。まとめサイト・報道・AI の答えは根拠にしません。
- 書いていないことは推し量らず、`unknown` のままにします。電話で問い合わせた結果を入れるときは、`route` を `office_reply` にして、問い合わせた日を書きます（担当者の名前は書きません）。

## 3. データを直す

直すのは `site/data/intake/chinjo.jsonl`（議会への陳情）か `yobo.jsonl`（首長への要望）の、その自治体の1行だけです。形の説明は [site/data/intake/README.md](../../site/data/intake/README.md) にあります。

例：「郵送でも受け付けます。市外の方の陳情は、議員に配付します」と書いてあった場合

```json
"methods": { ..., "mail": {"resident": "review", "nonresident": "distribute"}, ... },
"sources": [ ...,
  {"fields": ["methods.mail"], "quote": "郵送でも受け付けます。市外の方の陳情は、議員に配付します",
   "url": "https://www.city.example.lg.jp/gikai/chinjo.html", "checked_at": "2026-11-17",
   "route": "official_site", "confidence": "confirmed"} ]
```

- `quote` には、案内ページの文をそのまま写します（要約しない）。
- 値を `unknown` から変えたら、`sources` を必ず1つ足します。
- 住民以外の扱いの細かい決まり（「在勤・在学は除く」など）は `nonresident_rule` に書きます。

## 4. 確かめて送る

```sh
node scripts/intake.js check    # 形を確かめる
node scripts/intake.js export   # 作成画面用の site/data/intake.js を作り直す
npm test
```

プルリクエストには、調べた自治体と、見たページの URL を書いてください。案内ページが開けなかったとき（ボットの拒否・メンテナンスなど）は、その自治体と日付をプルリクエストに書いてください。[受け付け方の案内ページを取得できなかった自治体](受け付け方の案内ページを取得できなかった自治体.md) に足します。
