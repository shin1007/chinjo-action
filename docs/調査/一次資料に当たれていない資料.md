# 一次資料に当たれていない資料

陳情の文面に使う前に原文を確かめたいが、まだ確かめられていない資料の一覧。**この一覧を正本にする**（2026-11-27 に整理）。

- 同じ資料は1か所にだけ書く。1〜3の行には番号（`[U-001]` など。新しい行は今ある最大の番号＋1）を付け、ほかのファイルでは理由を書かずに「未確認（U-001）」と番号で指す。
- 確かめたら、その行を消して、いちばん下の「解決済み」に番号を付けたまま1行で移し、ほかのファイルで同じ番号を指す行を「確かめた」に直す。直し漏れは `npm test`（test/docs.test.js）が見つける。`archive.js` で保存すると、関係しそうな未確認の行を表示する。
- 運営者のTODO（`docs/非公開/運営者のTODO.md`）の「手で開いてほしいページ」には、開いてほしい URL だけを書き、説明はここを見る。
- 項目ごとの数字の確認は [項目の数字の確かめ直し.md](項目の数字の確かめ直し.md)。そこで「未確認」の行は、理由をここに書く。
- 自治体の受け付け方・回答の一覧が取れない自治体は、別のファイル（[受け付け方の案内ページを取得できなかった自治体.md](受け付け方の案内ページを取得できなかった自治体.md)、[要望書の出し方のページが見つからない自治体.md](要望書の出し方のページが見つからない自治体.md)、[回答の一覧を取得できなかった自治体.md](回答の一覧を取得できなかった自治体.md)、[回答をPDFで載せている自治体.md](回答をPDFで載せている自治体.md)）。受け付け方の根拠の一文を機械で照合して確かめられなかったものは [出典を確かめられなかったもの.md](出典を確かめられなかったもの.md)（`scripts/intake-verify.js` が書き出す）、X・note の規約は [SNS収益化の規約に当たれなかった資料.md](SNS収益化の規約に当たれなかった資料.md)。

手順：

- 人がブラウザで開いて「名前を付けて保存」したファイルは、`論文・一次資料・二次資料/手で保存（日付）/` に置き、`node scripts/archive.js <URL> "<題名>" "<メモ>" --file <保存したファイル>` で証拠として登録する（本文は sources/archive/、URL・取得日時・SHA-256 は site/data/archive-index.json）。
- 報道機関・個人のサイトは消えることがあるので、使ったら `node scripts/archive.js <URL> "<題名>"` で保存する。
- 裁判所の判例は `https://www.courts.go.jp/hanrei/{番号}/detail2/index.html`。検索は `https://www.courts.go.jp/hanrei/search1/index.html` を Chrome で開く（curl では弾かれる）。
- PDF から日本語が取り出せないとき（pdftotext で数字しか出ない）は、PyMuPDF（`import fitz`）で読むか、ページを画像にして読む。

## 取れなかった理由の区分

- 【BOT制限】サイトは動いているが、自動の取得を拒んでいる（403、空の応答、確認画面）。人がブラウザで開けば読める見込み。
- 【サイトダウン】サイト自体が止まっている、アドレスが変わった、証明書の不備。時間をおいて開き直すか、新しいアドレスを探す。
- 【その他】開けたが、資料が見つからない・載っていない・読み取れない・まだ試していない。

403 や空の応答が返ったものを BOT制限とした。同じ URL をブラウザの名乗りで開き直すことは、ボット対策をすり抜ける操作にあたるのでしていない。
